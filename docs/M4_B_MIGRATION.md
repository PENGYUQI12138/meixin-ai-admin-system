# M4-B 迁移设计与隔离操作

本文件是迁移设计，不是正式执行授权。用户本轮授权隔离修复、测试、验收材料及草稿PR；未授权合并、正式 migrate 或部署。

## 代码及数据变化

基线 `6fae2b9c978b3c812a0d999d01bec2dade9c3f80`。Frappe 16.34.0 / ERPNext 16.35.0 / MariaDB 11.8.9 / Python 3.14.7 保持原版本。

新增 7 个标准 DocType：4 个主要单据（规则、结算单、调整、付款）和 3 个子表（人数档位、计价行、覆盖关系）。新增 `Meixin Finance` 角色，不给既有真实账号自动分配角色。新增工资范围读取/导出权限，不把财务加入旧学生、课包和排课业务角色集合。

Frappe schema sync 创建表和字段；唯一约束包括规则生效日期、结算请求、来源占用、调整来源事件、付款请求/付款周期/冲正原记录。after_migrate 增加结算教师日期、来源覆盖、教师业务日、调整及付款查询索引。沿用旧时区对齐函数，财务角色加入站点时区对齐范围；不改全站时区和默认币种。

所有新工资金额显示和存储明确为 CNY。规则/结算已有 currency，档位/计价行及调整/付款有对应默认字段；客户端不能改变工资币种，付款必须传明确实际金额与核算版本供服务器在锁内校验，不再由服务器替换为净应付。查询、报表走无写锁读取，写服务继续使用原全站事务锁和 current read。

2026-10-25 Work 复核修订：在原付款类型上增核算版本、当时净应付、差异登记标识及依据；原调整类型上增更正目标、申请依据/人/时间、请求快照、目标指纹及批准/驳回决定。不新增类型、不回填旧付款或调整事实，不将旧字段新增为必填导致旧账无法读取。源码与 Desk JS 需同批发布；旧付款客户端缺少实际金额/版本时明确拒绝。只在两个隔离站先备份后迁移，正式迁移仍未授权。

不回填工资、不从旧分钟换算工资、不修改旧课消或权益流水，不导入样例/演示业务。M4-A 教师事实只新增确认及撤销后的同步通知调用；异常仍整笔请求回滚。新的规则版本必须由财务明确创建和提交。

## 隔离开发站

- 项目：`meixin_m4b_test`；站点：`test_meixin_m4b.localhost`；入口：`http://127.0.0.1:18085`。
- 自有 DB/sites 卷及网络；不挂载 frappe_docker 的卷、文件或网络。
- 原有测试脚本增加 M4B 白名单、18085 端口；frontend 只读挂载本 app public，用于加载工资 Desk JS。没有改正式 Compose 或原衍生镜像文件。
- 密码保存在源码外 `work/m4b-test-secrets`，不得放入 Git、测试报告或补丁。浏览器用户和全部数据均为虚构 UAT。
- 完整自动回归使用无 UAT 冲突的隔离事务/站点；工资规则的生效日期为机构级唯一，不能为了重跑测试删除既有 UAT 规则。验收报告分别记录完整回归、边界单跑和后续复核。

从本独立检出运行既有命令即可操作此测试项目（以下不是正式站命令）：

```powershell
.\deploy\test-env.ps1 -Generation M4B -Action status -ScratchDirectory '<本机源码外密码目录>'
.\deploy\test-env.ps1 -Generation M4B -Action test -ScratchDirectory '<本机源码外密码目录>'
```

有 UAT 规则时不要直接把测试失败当产品错误；完整回归应使用独立无冲突环境。所有测试入口先校验固定测试站名、双测试标志，且只支持 MariaDB；并发 worker 另查 TEST 批次。frontend 不在白名单中。

## 回退原则

隔离代码可回到本分支的已记录 checkpoint，保留原检出和测试卷，不清库或删除已有成果。正式迁移尚未执行，没有正式回退动作。

Frappe schema sync 不是一个可整体回滚的 SQL 事务。发生迁移错误时保留现场和最新备份，优先修复前进；不能卸载 app、删表或删 volume 代替恢复。若已有 M4-B 业务写入，单退镜像也不能移除关联逻辑后继续业务。

确需恢复时，必须重新确认目标站、停写范围和最新备份批次，使用匹配 DB、文件、配置和代码的整套材料；先保留部署后新增业务并确定处理方式。禁止用过去 M3/M4-A 旧备份自动覆盖当前正式库。本轮未实际恢复任何正式或既有隔离数据库。
