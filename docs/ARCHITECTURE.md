# M1 架构

## 原生结构

独立 Frappe App `meixin_admin`，模块 `Meixin Admin`，七个标准 DocType。四类档案与排课自动编号、启用变更记录，学生姓名和监护人电话不唯一；教师 `user` 可空，非空由数据库唯一约束保护。`MX Session Student` 是子表，权限继承父排课。`MX Settings` 为 Single，只存机构名称，不更改 System Settings。

DocType JSON、控制器、Role fixture、Workspace、日历配置、翻译与迁移 hook 全部进入源码。安装不灌演示数据，不授予用户任何角色。没有独立网站。

## 提交事务与并发

MariaDB 是本轮支持和验证的数据库。`SchedulingDocument.insert` / `_save` 在 Frappe 锁定具体文档之前，对稳定元数据行 `tabDocType.name='MX Session'` 执行 `SELECT ... FOR UPDATE`。同站点所有排课和档案写入共用这个锁。

锁由数据库事务持有到请求成功提交或异常回滚；不是有超时自动失效的缓存锁，也不是“查询后就释放”的锁。提交、取消、档案停用、容量变更、演示初始化使用同一顺序，减少交叉锁造成死锁的风险。Frappe 底层数据库事务仍可能因站外写入/管理操作发生死锁，必须把整个请求失败回滚后重试，不能绕过锁。

获得锁后，对关联档案、有效排课和学生子表重新执行锁定读取。MariaDB 11.8 默认开启 snapshot isolation，如果事务旧快照无法取得新版本行锁，会返回 1020 并终止事务。App 对数据库锁冲突/超时显式全事务回滚，显示中文“请重新加载后再提交”，不会忽略错误继续写入或在同一旧快照重试；未改变数据库全局隔离设置。[MariaDB 官方说明](https://mariadb.com/docs/server/server-usage/storage-engines/innodb/innodb-system-variables)。核心条件：

```text
旧单 docstatus = 1
新开始 < 旧结束 AND 新结束 > 旧开始
教师相同 OR 教室相同 OR 至少一个共同学生
```

使用完整 Datetime，10:00 衔接允许，跨日/午夜无需截断。草稿照常校验名单、时间、容量、启用状态，但不查询占用；提交重新校验并检查冲突。取消把 docstatus 改成 2，只有事务提交后才释放占用。已提交排课禁止更新，通过取消→修订→重新提交变更。已提交或已取消的排课不能删除，以保留历史；管理员仍可删除未提交草稿。

粗粒度锁意味着同一时刻一个写事务，适合 4 名行政、每周末约 30 节课。长时间不提交的外部 Console 事务会阻塞其他写入；日常使用 HTTP 表单/API，不在持锁期间等待人工输入。后续只有测得锁争用后才考虑资源锁，不能牺牲检查与写入的原子性。

Frappe 的请求事务负责失败回滚；App 不在控制器中手动 commit。服务端 Console/自定义脚本若捕获异常，调用者必须 rollback，不得把失败事务的中间状态提交。标准测试会验证失败后的数据库状态。

## 档案保护

停用档案时检查结束时间仍在未来（包括正在进行）的已确认排课。缩小教室容量时逐一检查这些排课实际学生子表人数。并发提交和这些修改使用同一锁，所以不会出现检查完成后被另一行政插入有效引用的间隙。

## 权限与隐私

| 能力 | Meixin Manager | Meixin Scheduler |
|---|---|---|
| 档案读取、新建、修改 | 是 | 是 |
| 排课草稿、提交、修订 | 是 | 是（修订需已有取消单） |
| 取消、删除草稿 | 是 | 否 |
| 设置读取/维护 | 是 | 否 |
| 默认批量导出、分享、导入 | 否 | 否 |
| 管理用户和角色 | 不授予 | 不授予 |

Guest 和无业务角色用户被 DocPerm 及业务角色 gate 双重拒绝。Frappe 自带 `Administrator` 是平台超级用户，保留其框架权限，不创建替代超级账号。没有把普通 System Manager 用户默认加入美心角色。

日历 API 先检查业务角色与 DocType 读取权限，再用权限感知的 `frappe.get_list` 查询，逐单复核读取权限。筛选字段仅允许教师/教室，不接受任意 SQL/字段/排序。默认排除取消，查询跨度最多 93 天。冲突检查需要全局占用视图，但只有拥有冲突排课读取权时才输出对象和时段；否则仅提示联系管理员。不会返回名单或监护人电话。

学生与监护人联系资料只用于机构内部档案；没有外部请求或导出集成。HTML 插入使用框架安全显示/显式编码。App 无新增运行时第三方依赖。现有框架依赖未升级，不能把本轮业务测试当成整个 ERPNext 依赖安全审计。

## 后续边界

后续按实际需求新增：学生→课包→实收登记与课次流水；排课→名单→考勤→课次流水；实际授课确认→教师应付流水→结算单。学生课次、教师工时、人民币金额分别建账，不能混在单节排课中。此轮没有这些业务的 DocType 或空壳界面。
