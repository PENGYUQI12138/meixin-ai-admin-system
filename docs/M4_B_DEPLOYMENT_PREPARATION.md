# M4-B 下一阶段部署准备清单（2026-10-28）

本页只整理下一阶段条件，没有执行容器、数据库、配置、镜像构建或部署操作。用户本轮仅授权合并及代码封存；正式部署须另行授权。

1. **确定候选与当时现场。** 用最终 M4-B 验收标签解析出的提交、源码指纹和固定镜像摘要记录候选；重新核对 `frontend / frappe_docker / localhost:8080`、六服务、现库应用/框架版本、工作区、挂载及生效配置。不要只看 `meixin_admin 0.1.0`。在获授权范围只读核对最新业务、授课及撤销状态、历史人数依据，以及 7 个新 DocType、字段、角色、权限和索引是否与既有自定义内容冲突；不沿用 10 月 22 日“业务表为空”。

2. **取得当时的成套可恢复备份。** 在明确停写与后台消费者安排后，新备份 DB、公私附件、site_config/encryption key、公共配置、apps.txt、应用源码/版本、旧运行镜像及实际 Compose 文件；校验摘要、完整可读性并在独立环境演练恢复。备份和凭据仅本机受保护保存，保留旧批次。单独盘点远程 File 资源；旧部署报告明确远程资源内容不在本地附件备份内，不把旧数量当作当前数量。

3. **演练正式历史副本升级。** 使用获授权、记录采集时点及范围的最新正式历史副本，在自有 DB/sites/网络的隔离环境按同版本 M4-A→封存 M4-B 迁移；保持 Frappe 16.34.0、ERPNext 16.35.0、MariaDB 11.8.9、Python 3.14.7。比较旧业务、余额、关联、设置、权限、实际角色和文件，核对新表及所有唯一约束/索引；记录正常框架元数据变化，不能回填时间掩盖。现有虚构历史成功不代替该验证。

4. **验证正式镜像与客户端资产。** 构建包含封存 Python 源码及 public/Desk JS 的镜像，核对 `/assets/meixin_admin/...` 发布路径、实际 HTTP 和普通角色页面；Python 与 JS 同批更新并处理缓存。旧付款窗口缺实际金额或核算版本应明确拒绝，不能静默回退。隔离 frontend 的只读 public 挂载成功，不等于正式构建/资产已验证。

5. **审查维护窗口和切换方案。** 沿用实际三层 Compose：原 `pwd.yml`、原 M3 覆盖文件、当前 M4-A 覆盖文件；未来新增候选覆盖也须先核对合成配置。仓库内 `deploy/pilot-compose.yml` 仍写 M2 标签，不能把它直接当成当前正式基线。明确停入口、worker、scheduler的顺序，避免新旧代码并发处理；只在另获授权后更新六个应用，固定项目名及 `--no-deps`，不运行 configurator/create-site/install-app/seed，不重建 DB、Redis 或卷。记录维护及 scheduler 原值，验收后恢复。

6. **明确角色、规则及开放判据。** 由授权人员给指定财务老师分配 `Meixin Finance`，不把行政自动升级为财务；财务明确建立首个生效工资规则。核对六服务镜像一致、DB/Redis/队列健康、HTTP/Socket.IO/资产、来源摘要最小读取、行政不能批准/付款、报表及导出权限、新表/索引、旧记录/余额/角色保持。业务写入验证仍在隔离站，正式站不造测试课程、工资或付款；所有判据通过后才开放真实业务。

7. **区分开放前恢复和开放后纠错。** Frappe schema sync 不能整体 SQL rollback，单退镜像也不能撤销迁移。失败时保持停写、保留日志与失败状态，优先修复前进；确需恢复时，仅按另获授权的方案恢复匹配 DB、配置密钥、文件、源码/镜像和 Compose。开放后若有新增授课、工资或付款，先保存新增事实并重新确定处理方案，不自动拿旧备份覆盖、不删表/卸载 App/删卷。
