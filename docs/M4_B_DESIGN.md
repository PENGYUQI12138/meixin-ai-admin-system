## 已确认规则

1. 正常课程一节固定 90 分钟，逐节独立计价，不按分钟除以 90 折算。班级人数 4 人及以下 100 元、5 人及以上 120 元，不读当次到课人数定价。
2. 冻结排课名单仅预填人数。行政确认包含请假、缺勤学生；名单不完整时补计薪人数和依据，依据不足保持待核对。现有系统没有独立班级成员生效历史，不把当前名单当历史。
3. 单价和人数档位按生效版本选择；保存人数、规则、金额、来源及核对快照。已批准原账冻结。
4. 固定费用可覆盖教师指定日期全天授课，或明确指定课程、工作事项；金额、原因、覆盖范围必填。范围内不重复按节，范围外可另行结算。全天覆盖后补录同日课程产生重新核对事项。
5. 行政核对课次及人数；财务批准金额、登记实际线下付款。页面与 API 均禁止行政批准、付款。
6. 每张单按净应付整单一次付款，不分次付款；来源不能跨单重复纳入。错误付款登记追加冲正，保留原记录；冲正后可按当时净应付重新登记。
7. 临时取消不产生该课次应付。固定费用部分课程取消交财务按约定调整，不机械扣整笔固定费用。
8. 非 90 分钟、无人到课、教师归属争议等不能自动进入正常计薪。事实错误走原取消修订；特殊金额说明原因并由财务批准。M4-A 的分钟取整、15 分钟异常阈值不用于工资舍入。
9. 零应付不生成付款，负应付保留待财务事项，不自动扣下期工资、不视为已退款。
10. 继续 M4-A 原排课单教师边界，不支持或宣称支持代课、共教。

## 最小结构和状态

- `MX Teacher Pay Rule`（生效日期唯一、可提交）及 `MX Teacher Pay Rate`（人数下限、上限、金额）。财务维护；已提交版本不可修改或取消，通过新增版本变更。
- `MX Teacher Pay Sheet`（单教师、日期范围、待核对→已核对→已批准）及 `MX Teacher Pay Line`、`MX Teacher Pay Coverage`。普通课程、特殊课程金额、固定费用共用明细。覆盖表统一占用原排课修订链、全天教师日期或工作事项键；待核对草稿不占用，核对时原子占用，撤回后释放，批准后不释放历史来源。
- `MX Teacher Pay Adjustment`：原结算行、来源事件、原因及建议金额；财务说明决定金额后提交。来源事件唯一，不修改原账。已批准未付款的调整进入该单净应付；已付款保留原付款及调整，差额继续标为待处理，不自动转下期或标为退款。
- `MX Teacher Pay Payment`：只经服务新增的不可变付款/冲正，记录时间、方式、参考号、登记人及请求键。冲正唯一引用原付款；普通重复登记不被当作冲正后重登。

批准前重建并比较核对快照：来源有效性、行政人数依据、当日规则、覆盖课程集合或金额变化时拒绝批准并要求重新核对。批准后单据不可改、不可取消，所有更正追加调整。

所有写操作沿用 `schedule_write`，先取得全站事务锁再 current read；请求失败回滚，不在业务函数手动 commit。原排课和执行单 `amended_from` 链防循环校验，稳定课次身份不随取消重确认变化。全日占用与指定范围占用在同一锁中交叉检查，数据库唯一 active_key 是最终防线。

指定范围固定费用允许覆盖本单日期范围内不同日期的明确课程；明细 pay_date 是费用归属日，每个来源占用仍记录真实授课日，以便与对应日的全天覆盖交叉防重。同一明确工作事项按教师及规范化 work_key 跨日期唯一，不得靠更换归属日重复计费。

教师课时确认/撤销后，同事务产生必要的后补或撤销调整。未批准单的失效来源阻止继续批准；已批准相关单的待处理调整暂停付款。调整生成失败使来源操作整体回滚。取消普通课程建议冲回原金额；固定费用仅产生待核对事项，由财务决定差额。

## 接口约定（便于并行实现与测试）

模块 `meixin_admin.teacher_payroll`，所有公开写 API 都校验角色、输入、文档读取权限、同请求内容一致及数据库唯一性：

- `create_sheet(teacher, from_date, to_date, lines, request_id)` / `update_sheet(sheet, lines)`：行政操作，lines 接受 JSON 数组或列表。
- 行输入：`kind` 为 `课程`、`特殊`、`固定`；`hour_entry`；`class_size`；`headcount_basis`；`exception_reason`；`amount`；`pay_date`；`scope` 为 `全天` 或 `指定`；`hours` 为固定费覆盖的课时确认 ID 列表；`work_key` 为明确工作事项标识；`description`。
- `check_sheet(sheet)` / `withdraw_sheet(sheet)`：行政核对或撤回未批准单。行政核对必须提供实际教师归属无争议、人数完整等依据，特殊金额填写原因。
- `approve_sheet(sheet)`：仅财务，重新检查核对快照并提交。
- `approve_adjustment(adjustment, amount, reason)`：仅财务，原账不变，提交调整决定；同内容重试返回原项，不同内容拒绝。
- `record_pay_payment(sheet, paid_at, payment_method, reference_no, request_id, actual_amount, balance_version)`：仅财务，必须明确确认实际付款金额及打开窗口时的核算版本。两者纳入请求幂等内容，事务锁内以当前数据复算版本并核对金额；版本变化或实际金额不等于整单净应付时拒绝，不替换输入。旧客户端缺少两项输入时拒绝。
- `record_pay_difference(同上, reason, basis)`：独立的已发生付款差异登记，仅财务在重新核对当前版本后使用；保存真实实际金额、当前核算额、差异原因及依据。允许当前净应付零/负或仍有待处理调整时保留已发生的真实正数付款，不替代正常付款批准；保留待处理状态，不自动退款/扣款。与普通付款共用单活动付款和冲正周期唯一约束，不增加分次付款或补款功能。此事实登记不要求已付之后授课来源仍有效。
- `request_pay_correction(sheet, amount, reason, basis, request_id, line_index=None, related_adjustment=None)`：行政或财务申请，二选一关联已批准原结算行或同单已批准调整。amount 为追加差额，不是更正后的总额。保存原目标、已批准调整集合、原因、依据、申请人及幂等请求快照，不修改原账和课次占用。
- 更正申请仍由 `approve_adjustment` 财务批准；目标快照或已批准调整集合变化时拒绝，防止并发申请基于同一旧金额重复批准。`reject_pay_correction(adjustment, reason)` 仅财务对更正申请作出明确驳回决定并保留零金额记录；不允许驳回来源撤销事项。旧申请被驳回后可重新核对、另提新请求。驳回不等于批准零元，原决定不可改写。
- `reverse_pay_payment(payment, reason, request_id)`：仅财务，追加唯一反向付款；不表示银行撤回或已退款。
- `get_pay_balance(sheet)`：权限感知的原批准额、已批准调整、净应付、有效付款、差额、状态及核算版本。版本包含父单核对身份、调整状态和付款/冲正事实；金额恢复相同也不会恢复旧版本。写操作使用框架原生 for_update 文档加载，不在锁定名称后读取旧事务快照。
- 调整批准及普通/差异付款保存前，在同一事务锁内验证操作后的净应付、有效付款及最终差额均符合原精确金额范围；超限在写入批准或付款前拒绝，不能保存后才导致余额或报表读取失败。恰为允许上限的差额仍合法。
- `get_source_summary(hour_entry)` / `list_pay_sources(teacher, from_date, to_date)` / `list_pay_teachers()`：只返回教师/课程名称、课次标识、时间、名单人数、是否有人到课及异常类别等履职摘要，不返回学生姓名、电话、名单、执行单原文或来源原因原文。

普通课程原始起止恰为 90 分钟、正分钟且有学生到课、无时间异常/归属争议才可正常计价。特殊课程只能引用有效已授课来源；不能用特殊金额给已取消课程绕过计薪限制。独立工作事项使用固定费的 work_key/description，不冒充授课来源。

## 权限与界面

工资角色 gate 与旧业务角色 gate 分开。`Meixin Finance` 不加入旧 `BUSINESS_ROLES`；不开放教师/学生/排课/执行单原始文档。工资快照中教师及来源标识使用 Data，通过受控摘要接口查看。报表和 CSV/XLSX 导出都校验工资读取权限。禁止单独 DocShare；无业务角色、Guest、仅 System Manager 不能绕过。

复用 Desk 单据与 Script Report；不引入独立前端、银行转账、完整会计总账或通用薪酬引擎。管理员超级账户仍遵循框架能力，业务权限不声称限制数据库管理员。

报表日期条件仅筛选工资明细；整单净应付、有效付款和差额在首个所选明细行展示，列名明确“整单”，每行同时给出完整结算期间。页面提示与CSV/XLSX导出采用同一范围定义，不按所选课程或日期分摊实际付款。
