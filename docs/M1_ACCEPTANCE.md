## 浏览器控制台和实时连接

首次检查发现测试入口没有代理 `/socket.io`，浏览器收到 404。随后正式入口暴露了两层独立问题：浏览器公开的 `localhost:8080` 与容器内部 Host/Origin 不一致会产生 `Invalid origin`；直接把公开地址传给独立 WebSocket 容器，又会使其把 `localhost` 解释为自身，认证回调产生 `fetch failed`。

最终使用同一可配置 Nginx 启动脚本：正式 Compose 的 Socket.IO 认证使用内部可达且相互匹配的 `Origin: http://frontend:8080`、`Host: frontend:8080`；隔离 Compose 使用 `http://app:18081`、`app:18081`。浏览器仍通过各自公开同源入口访问。隔离 App 容器重建时也不再下载 Python 构建依赖。

修复后验证：

- 登录入口返回 HTTP 200。
- `GET /socket.io/?EIO=4&transport=polling` 返回有效 Engine.IO 握手包。
- 在全新浏览器页重新加载带教师与教室筛选的周课表，控制台结果为 `[]`，即 0 条 error、0 条 warn。
- Windows 正常关机恢复后，隔离入口再次在全新页面显示带筛选的周课表和既有虚构记录，控制台仍为 `[]`。
- 冲突提交旧页曾记录一次 Frappe `ValidationError`，它对应验收时故意触发并由界面正确显示的业务拒绝，不是未处理的成功路径错误。
