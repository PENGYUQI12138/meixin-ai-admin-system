# 美心行政 M2 设计

最后更新：2026-09-21（Asia/Shanghai）

## 目标与边界

M2 只建立“已确认排课 → 实际执行 → 学生考勤 → 不可变课消决策流水”闭环。`MX Session` 继续作为 M1 冻结的排课源单；不在已提交排课中加入考勤字段，不放宽冲突、取消、修订或历史保护规则。

本里程碑不实现学生课包余额、剩余课时、充值、收费、支付、财务、教师工资、微信、家长端或 AI 排课。课消流水记录一次业务决定，不承担余额扣减。

稳定基线为 `29d622e3e2b946170aa36fe51fbebeb5f2bf3719`。M2 仅在 `m2-attendance-consumption` 分支前进，不 rebase、reset、amend 或 force push M1 历史。

## 数据关系

```text
MX Session（M1 排课源单）
  ├── MX Session Execution（可提交的执行单）
  │     └── MX Session Attendance（考勤子表）
  └── MX Lesson Consumption Entry（不可变决策流水）
          └── reversal_of → 原流水
```

### MX Session Execution

执行单使用 Frappe 原生 `docstatus` 生命周期：

- 草稿：填写考勤，不产生课消流水。
- 提交：实际执行完成，冻结考勤和规则结果，并在同一事务生成流水。
- 取消：只有 `Meixin Manager` 可以执行；追加 reversal 流水，不覆盖旧流水。
- 修订：只有 `Meixin Manager` 可以从已取消执行单建立新草稿；重新提交产生新的决定流水。

每个执行单引用一个已确认的 `MX Session`。名单必须与源排课完全一致，不得添加、删除、替换或重复学生。同一排课同一时刻最多一个 `docstatus=1` 的有效执行单；检查与写入在现有站点级排课事务锁内完成。

执行单保存以下审计信息：源排课、考勤明细、提交时采用的规则结果、实际完成人和完成时间，以及提前完成原因（如适用）。源排课的课程与计划时间不复制成可编辑字段；流水会保存必要快照。

### MX Session Attendance

每名源排课学生恰好一行，状态限定为：

- 到课
- 请假
- 缺勤
- 其他

“其他”必须填写说明。草稿中状态可编辑；执行单提交时，每行冻结 `consumption_rule_result`（课消或不课消）。设置日后变化不回写已提交考勤。

### MX Lesson Consumption Entry

流水只允许业务服务创建，普通用户和业务角色均不能直接新增、修改、取消或删除。字段至少包括：

- `student`、`session`、可选 `execution`
- `course`、计划开始/结束时间快照
- 学生/课程名称快照
- 考勤或课程取消结果
- `operation_type`（决定、撤销）
- `effect`（1、0、-1）
- `reversal_of`、原因
- 数据库唯一的 `idempotency_key`
- Frappe 内置创建人和创建时间

效果语义：

- `+1`：本次产生一次课消。
- `0`：明确决定本次不课消；必须保留，不能省略。
- `-1`：对原 `+1` 的反向撤销。

取消执行单时，每条原决定都追加 reversal：原 `+1` 产生 `-1`，原 `0` 产生带 `reversal_of` 的 `0` 撤销记录，以便区分“决定仍有效”和“决定已撤销”。人工撤销课消只允许 Manager 对仍有效的 `+1` 执行，必须填写原因，并追加唯一 `-1`；旧记录永不覆盖。

## 状态机

排课实际状态由源单和执行单派生，不在两处保存可漂移的状态字段：

| 条件 | 实际状态 |
|---|---|
| `MX Session.docstatus=1` 且无有效执行单 | 待上课 |
| 存在 `MX Session Execution.docstatus=1` | 已完成 |
| `MX Session.docstatus=2` | 已取消 |
| 最近执行单已取消且排课仍确认 | 待纠正 |

存在已提交执行单时，禁止直接取消源排课。必须先由 Manager 取消执行单，使流水反转，再取消源排课。源排课取消仍保留 M1 的不可删除和修订链。

## 课消规则

`MX Settings` 为五种结果分别保存三态配置：`未配置`、`课消`、`不课消`。

- 到课
- 请假
- 缺勤
- 其他
- 课程取消

安装或迁移不擅自填写规则。涉及的规则为“未配置”时，提交执行单或取消排课必须失败，并明确提示由 `Meixin Manager` 先完成规则配置。

执行单提交时把本次实际结果冻结到考勤行和流水。排课取消时按“课程取消”规则为原名单每名学生生成 `+1` 或 `0` 流水；若规则未配置，整个取消失败且不产生部分流水。

## 完成时间规则

- Scheduler 只有在源排课计划结束时间到达后才能提交执行单。
- Manager 可以在计划结束前提交，但必须填写非空的提前完成原因。
- 提交人、提交时间和原因随已提交执行单保留，修订不会覆盖原记录。
- 使用 Frappe 站点时间 `now_datetime()` 与计划结束时间比较，不修改系统时间，不使用客户端时间。
- M2 初始实现不设置时钟误差宽限窗口；现场容器内业务判断使用同一服务器时钟。若以后观测到真实的节点时钟漂移，再单独评估一个有记录的小窗口。

## 权限

| 能力 | Meixin Manager | Meixin Scheduler |
|---|---:|---:|
| 查看执行单、考勤和流水 | 是 | 是 |
| 创建、填写、保存和提交执行单 | 是 | 是 |
| 提前完成并填写原因 | 是 | 否 |
| 取消和修订执行单 | 是 | 否 |
| 人工撤销课消 | 是 | 否 |
| 修改课消规则 | 是 | 否 |
| 直接增删改流水 | 否 | 否 |

`Administrator` 保留 Frappe 超级用户能力，但 App 控制器仍保护流水不可变性。新 DocType 继续使用业务角色 gate、DocPerm、User Permission 和禁止临时分享策略。

## 幂等、事务和锁

执行提交、执行取消、人工撤销和源排课取消复用 M1 的 MariaDB 站点级 `SELECT ... FOR UPDATE` 写锁，不新增 Redis 锁或第二套锁顺序。

建议幂等键：

```text
execution:<execution>:<student>
execution-reversal:<original-entry>
session-cancel:<session>:<student>
manual-reversal:<original-entry>
```

`idempotency_key` 在 DocType 中设为数据库唯一字段。服务在锁内检查已有记录；重复请求内容一致时返回既有结果，内容不一致时失败。数据库唯一约束作为并发兜底。

一个请求事务内完成状态复核、名单复核、规则冻结、执行提交和全部学生流水写入。任何一行失败都依赖 Frappe 请求事务整体回滚；控制器不手动 commit。MariaDB 锁冲突继续使用 M1 的整事务 rollback 和中文重试提示。

## 取消、修订与回溯

- 普通编辑不会重新生成流水。
- 执行取消只追加 reversal，不修改原决定。
- 修订生成新执行单和新的幂等键；原执行单及流水永久保留。
- 人工撤销必须指向一条未撤销的 `+1`，必须有原因；同一原流水最多一个有效人工撤销。
- 课程取消的决定直接追溯到源排课；被取消的排课不能复活，后续调整使用 M1 修订产生新排课。
- 流水中的学生、课程、计划时间和结果快照保证档案显示名称后续修改时仍可审计。

## 测试与部署边界

M1 30 项必须完整回归。M2 增加规则未配置、四种考勤、课程取消、提前完成、权限、重复请求、双击、并发提交、并发取消、规则快照、撤销、修订、直接流水篡改、失败整体回滚和 User Permission 隐私测试。

所有迁移和写入测试先在 `test_meixin_m1.localhost` 执行。正式 `frontend` 不运行测试、不创建测试业务数据。正式部署前重新完整备份，并单独说明 schema 变化、容器重建、停机窗口和恢复方法，获得确认后才能执行。
